# 运行维护

[文档导航](README.md) · [安装与升级](installation.md)

## 配置与监听

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| `PORT` | 已保存端口，否则 `8787` | 临时覆盖端口，不修改数据库 |
| `LISTEN_HOST` | 已保存地址，否则 `127.0.0.1` | 临时覆盖监听地址，必须是 IPv4/IPv6 地址 |
| `DATABASE_FILE` | 项目根目录的 `data/kukuai.sqlite` | 数据库路径，父目录需可写 |
| `ADMIN_TOKEN` | SQLite 中保存或自动生成的令牌 | 非空显式值优先，不自动写入数据库 |
| `API_KEYS` | 空 | 逗号分隔的普通 API 密钥，与控制台创建的密钥共存 |
| `CORS_ORIGIN` | `*` | 跨源访问允许的 Origin |
| `AUTO_CLAIM` | 未启用 | `1` 可启用每日领取；通常在控制台配置 |
| `KUKU_BASE_URL` | `https://kuku.baidu.com` | 模拟上游测试使用 |

一键新装将 `0.0.0.0` 保存到 SQLite；未经安装器初始化的源码启动默认回环地址。启动时环境变量优先于保存值。安装启动器清除 HTTP/HTTPS/ALL 代理环境变量，使上游请求直连。

公开监听时，普通密钥为空也不开放匿名模型调用。仅绑定 `127.0.0.1` / `::1` 的本地模式保留空普通密钥免鉴权行为。管理员接口始终验证管理员令牌。

## 反向代理

生产包中前端页面与后端 API 由同一实例提供，共用端口。反向代理将整个站点转发至该端口即可；控制台从浏览器页面识别外部 HTTP/HTTPS 地址，不需要填写内部回环地址。

- 同时转发页面、静态资源、`/healthz`、`/pool/*` 和 `/v1/*`。
- 保留认证头；SSE 对话响应需要关闭代理缓冲，并设置足够的读取超时。
- 只允许代理访问后端时，可设置 `LISTEN_HOST=127.0.0.1`，由代理终止 HTTPS。
- 分开部署前后端时，按实际域名配置 `CORS_ORIGIN`，在控制台填写后端根地址。

安装器不配置防火墙或 HTTPS 证书。

## 数据存储

SQLite 保存账号凭据、普通密钥、会话映射、Responses、对话正文、用量、日志及系统设置，使用 WAL。面向单实例运行，不支持多个服务进程同时共享号池调度状态。

旧版根目录 JSON 在首次迁移时事务导入，原文件保留；迁移完成后不再作为当前状态文件读写。数据库损坏或版本不兼容时拒绝启动，不回退为空配置。

安装器升级前保存源码与 SQLite 一致性备份到 `.runtime/backups/`。这些备份包含账号和令牌，与 `data/` 一样需要私有保管，不能公开。

## 备份与恢复

推荐停止服务后保存完整 `data/` 目录；自定义 `DATABASE_FILE` 时保存实际数据库及相关文件。在线备份使用 SQLite 一致性备份 API 或其他一致性快照方式，不能仅复制主文件遗漏 WAL。

恢复顺序：

1. 停止服务，保存当前数据库副本。
2. 恢复选定的一致性快照；不将不同时间点的主库和 WAL 混用。
3. 核对原有数据库路径、显式管理员令牌和监听配置。
4. 启动后检查账号、密钥和系统设置，再恢复日常使用。

保留策略不会清理独立备份及旧 JSON；需要自行管理这些文件。

## 账号登录凭据续期

控制台号池页提供自动续期开关、周期设置及单号/全部刷新。默认每 6 小时检查，账号之间间隔 15 秒；正在对话或领取积分的账号推迟处理。配置与检测记录保存到 SQLite，重启后继续使用。

自动续期通过 BDUSS + PTOKEN 换取并核验 STOKEN，不发送模型对话。旧账号未保存 PTOKEN 时，重新扫码或短信登录同一账号即可更新原记录，保留 ID、别名、优先级和停用设置。BDUSS/PTOKEN 已失效或被撤销时仍需重新登录。

上游未提供 STOKEN 的精确到期时间，控制台显示实际检测、刷新及下次计划时间。Cookie 的长期保存期限不能作为服务端 Token 的有效期；接口与处理规则见 [API 文档](api.md#账号登录凭据续期)。

## 日志与保留策略

控制台设置支持日志与对话保留天数，`0` 表示长期保留。修改后立即清理已过期数据，并在启动及每小时继续执行。

新安装默认日志保留 7 天、对话长期保留；升级保留已有设置。

对话清理会移除相关旧 Responses 映射，可能影响续聊；累计用量仍保留。`store:false` 不保存正文/思考，只保存用量和最小续接元数据；已有备份不会因此自动删除。

日志不记录请求头、请求体或查询字符串，系统消息经过凭据脱敏。排障时仍不要公开整个数据库或未经检查的本地抓包。

## 后台服务管理

一键安装、升级、`start.sh` / `start.ps1` 验证后台实例启动成功后返回终端，并显示完成提示、控制台地址和管理员密钥。`--no-start` 明确显示未启动，不会声称服务正在运行。开发者 `npm start` 保留前台运行方式。

Linux root + systemd 环境自动创建按安装目录区分的 `kuku2api-<目录哈希>.service`，启用开机启动，异常退出 3 秒后重启（受 systemd 启动频率限制）。关闭 SSH / 宝塔终端不影响系统服务。取得当前安装的服务名后可管理：

```bash
cd ~/kuku2api
node_bin=node
[ ! -x .runtime/node/bin/node ] || node_bin=.runtime/node/bin/node
unit="$($node_bin --input-type=module -e 'import { serviceName } from "./scripts/background-service.mjs"; console.log(serviceName(process.cwd()))')"
systemctl status "$unit"
journalctl -u "$unit" -n 100 --no-pager
systemctl stop "$unit"
systemctl start "$unit"
```

其他环境使用独立后台进程，输出保存到 `.runtime/server.log`，关闭终端后继续运行，但不自动开机启动或异常重启。停止可调用下方受保护的停止接口。

后台配置私有保存在 `.runtime/service.json`；systemd 使用 `.runtime/service.env`。仅保存应用配置，不复制整个登录会话环境；文件可能含显式管理员令牌/API 密钥，不要分享。后续启动和升级沿用保存值，当前显式环境变量优先。源码 `npm start` 不自动读取这些文件，继续使用启动环境和 SQLite 配置。

升级脚本验证目录、数据库和实例归属后等待请求结束，最长 120 秒；systemd 实例先显式停止托管服务，取消自动重启，再备份切换。启动失败会停止新实例再恢复旧版。API 主动正常退出不会触发 `Restart=on-failure`；长期禁用开机启动可用 `systemctl disable --now "$unit"`。不要通过结束所有 Node.js 进程处理端口冲突。

运行实例接口和停止请求格式见 [API 文档](api.md#运行实例管理)。
